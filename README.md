# PuppetForge

한 장짜리 PNG 캐릭터에 관절을 찍고 영향 영역을 칠해, 게임에서 바로 재생할 수 있는
2D 종이인형 애니메이션을 만든다. **웹 편집기**와 **게임용 런타임** 두 부분으로 되어 있다.

| | |
| --- | --- |
| **편집기** | 브라우저에서 캐릭터를 만든다. 결과를 `<이름>.export.zip`으로 내보낸다 |
| **런타임** (`npm i puppetforge`) | 게임이 그 zip을 읽어 재생한다. 의존성 없음, gzip 9.9KB |

게임이 실행될 때 편집기 서버와는 **아무 통신도 하지 않는다.** 내보낸 파일만 있으면 된다.

설계 배경은 [기획서](./범용%20웹%20종이인형%20애니메이션%20툴%20개발%20기획서.md),
파일 포맷은 [docs/puppet-json.md](./docs/puppet-json.md)에 있다.

## 게임에서 쓰기 (Runtime)

```bash
npm install puppetforge
```

```ts
import { Puppet } from "puppetforge";

const 거미 = await Puppet.load("/monsters/거미.zip");   // 내 게임 서버의 파일 경로
거미.play("idle");
거미.on("impact", () => enemy.takeDamage());          // 애니메이션 이벤트 (기획서 42)

// 매 프레임
const vertices = 거미.update(dt);   // 변형된 정점(Float32Array), 멈춰 있으면 null
```

그리는 것은 게임 엔진의 몫이다. `puppet.uv` · `puppet.texture` · `puppet.mesh.indices`를
쓰던 렌더러에 넘기면 된다.

### Phaser라면 그리기까지 해 준다

```ts
import { PuppetCreature } from "puppetforge/phaser";

const 거미 = await PuppetCreature.load(this, "/monsters/거미.zip", { x: 400, y: 300 });
거미.play("idle");
거미.setFlipX(true).setScale(2);          // 보통의 GameObject처럼 다룬다
거미.onEvent("impact", () => enemy.takeDamage());
```

`Phaser.GameObjects.Mesh`를 감싼 것이라 `setPosition` · `setDepth` 같은 조작이 그대로 통하고,
씬의 `update`에 스스로 붙으므로 매 프레임 부를 것이 없다.
같은 캐릭터를 여러 마리 세워도 텍스처는 한 번만 올라간다.

동작하는 예제는 `example/`에 있다. `npm run dev` 후 `/example/`을 열고
편집기에서 내보낸 zip을 넣으면 된다.

| | |
| --- | --- |
| `Puppet.load(url \| bytes)` | 내보낸 zip이나 puppet.json을 읽는다 |
| `.play(name, { speed, strength })` | 재생. 없는 이름이면 `false`를 주고 넘어간다 |
| `.stop()` / `.setSpeed()` / `.setStrength()` | 재생 조절 |
| `.on(event, fn)` / `.on("*", fn)` | 애니메이션 이벤트. 돌려받은 함수로 해제 |
| `.update(dt)` | 시간을 굴리고 변형된 정점을 준다 |
| `.poseAt(name, time)` | 재생하지 않고 한 자세의 정점만 |
| `.animations` / `.uv` / `.texture` / `.mesh` | 읽기 전용 정보 |

라이브러리는 몬스터 수와 무관하게 **한 벌만** 들어간다 (gzip 9.7KB).

아직 없는 것: 애니메이션 블렌딩.
순서는 기획서 70을 따른다.

## 편집기를 직접 돌리기

이 저장소를 받아 편집기를 고치거나 돌려 볼 때의 이야기다.
라이브러리만 쓸 거라면 위의 `npm install puppetforge`면 된다.

```bash
npm install
npm run dev      # 개발 서버
npm run build    # 타입 검사 + 프로덕션 빌드 (dist/)
npm run preview  # 빌드 결과 미리보기
npm test         # 코어 로직 테스트
```

Chromium 계열 브라우저 + WebGL 환경을 기준으로 한다.

## 현재 상태 (v0.36.1)

기획서 70의 Phase 1 · 2 · 3 · 4 · 5 · 6 · 8까지 되어 있다.
변경 내역은 [`VERSION.md`](./VERSION.md)를 참고한다.

- Vite + TypeScript + Phaser 기반 프로젝트 설정
- 한국어 편집기 레이아웃 (상단 `파일` · `설정` 메뉴 / 관절 · 속성 패널 / 애니메이션 바 / 표시 토글)
- PNG · WebP 드래그 앤 드롭 및 `이미지 불러오기`
- **일러스트 교체(스킨 스왑)**: 기존 관절·영향 영역·애니메이션은 유지하고 그림만 바꾼다.
  이미지 크기가 달라도 관절과 칠한 영역을 상대 좌표로 맞춰 옮기며, 새 파일명으로 별도 저장할 수 있다.
- 캔버스 Zoom(마우스 휠) / Pan(빈 곳 우클릭 또는 휠클릭 드래그)
- **휴대폰에서도 쓴다.** 좁은 화면에서는 좌우 패널이 아래로 내려가고 하단 `관절` / `속성`
  탭으로 끌어 올린다. 캔버스가 화면의 85%를 차지한다. 두 손가락으로 확대 · 이동하고,
  한 손가락으로 빈 곳을 끌면 화면이 움직인다. 갤러리에서 사진을 바로 고를 수 있다.
  iPhone에서는 프로젝트·게임 내보내기를 ZIP 파일로 공유하고, 구운 PNG 시트는 공유 시트에서
  `사진에 저장`을 바로 고를 수 있다
- 관절 추가 · 삭제, 이름 · 부모 · 태그 · 강도 · 4가지 변형 방식 편집
- 41개 태그를 묶음별 버튼으로 붙이고 뗀다. 마우스를 올리면 설명과
  "이 태그를 쓰는 동작" 목록이 뜬다. 변형 네 가지도 버튼 + 툴팁으로 고른다
- **모든 태그가 실제로 무언가를 한다.** 프리셋이 찾는 대상(`track`), 움직임 크기를 곱하는
  성격 태그(`modifier` — `heavy` 0.55배 · `light` 1.6배 · `bounce` 1.35배 · `stiff` 0.2배),
  움직임을 만들지 않는 표시용(`hint` — `ground` 하나)으로 갈래가 나뉘고 툴팁이 그대로 말한다
- Soft(부드러운 움직임), Rigid(형태 유지), Pinned Soft(위치 고정·부드러운 경계), Fixed(완전 고정)를
  실제 Mesh 변형에 반영. 완전 고정이 주 영향인 자리는 부모·이웃 영향을 끊고 아예 멈추며,
  다른 관절과 영향이 같은 경계는 기존처럼 비율대로 섞여 부드럽게 이어진다
- 변형 방식은 기본이 모든 애니메이션 공용이고, `이 애니메이션에서만` 탭으로 하나만 덮어쓸 수 있다.
  대기에서만 발을 바닥에 묶어 두고 공격에서는 그대로 떼는 식이다
- 캔버스에서 관절점을 직접 집어서 위치 이동
- 관절점을 우클릭해 가로 또는 세로로 끌면 먼저 움직인 한 축만 크기를 편집하고, 애니메이션
  일시정지 중에는 그 시점의 해당 `scaleX` 또는 `scaleY` 키만 찍는다
- 재생 중에는 관절점 · 연결선이 자세를 따라 움직인다. 그림만 휘고 점은 제자리에
  박혀 있으면 지금 어디를 잡아야 할지 알 수 없기 때문이다 (키프레임 편집의 전제)
- **타임라인** — 고른 애니메이션의 시간 축. 눌러서 그 시점으로 가고, 끌어서 훑어본다.
  키가 찍힌 시각이 마름모로 보이고, 관절을 고르면 그 관절의 키가 밝게 강조된다.
  일시정지는 자세를 그대로 둔 채 시간만 멈춘다
- **그 시점에서 관절을 움직이면 키가 찍힌다.** 일시정지 상태에서 관절점 안쪽을 끌면 이동,
  바깥 링을 끌면 회전이다. 프리셋(태그 Track)이 이미 주고 있는 몫은 빼고 적으므로
  섞여도 두 배로 움직이지 않는다
- **찍은 키를 끌어서 옮기고 우클릭으로 지운다.** 직접 찍은 키만 손댈 수 있고,
  프리셋(태그)이 만든 키는 다른 관절까지 움직이므로 잠겨 있다. 마름모 밝기로 구분된다
- 타임라인의 **기본 키** 버튼으로 고른 관절의 움직이지 않은 자세를 기록하고, **키 삭제** 버튼으로
  우클릭이 없는 모바일에서도 현재 키를 지운다. 첫 키에는 시작·끝 원본 자세 보호 키가 자동으로 붙는다
- 우측 패널에 **그 관절이 직접 찍은 키 목록**(속성 · 개수)이 나오고, 재생 헤드가 키 위에 서면
  보간 방식을 `부드럽게` / `일정하게` / `뚝 끊어서` 중에서 고른다
- 좌측 상단에 실행 취소 · 다시 실행 버튼. 되돌릴 것이 없으면 흐려진다
- 관절 목록 드래그로 순서 정리, `×`로 삭제. 목록은 앞→뒤 레이어 순서이므로 영향 영역이
  겹치면 앞 관절이 우선해 뒤 관절의 찌그러짐이 앞으로 튀어나오지 않는다
- 관절점과 부모 연결선 표시, 상단 우측에서 표시 항목 켜고 끄기
- 이미지 크기에 맞춘 격자 Mesh 자동 생성과 변형 렌더링. 도트용은 `최소`(24칸)부터 `높음`(108),
  일반용은 `최소`(128, 기본) · `낮음`(512) · `보통`(1024) · `높음`(5120)이며, 나중에 바꿔도 칠해 둔 영향 영역이 새 격자로 옮겨진다
- 도트 그림 자동 판정 — 불러올 때 픽셀을 보고 정하고, 도트면 격자도 성기게 잡는다
- **자동 가중치** — 관절을 놓으면 영향 영역이 바로 깔린다. 부모에서 자기까지의 선분에서
  가까운 정점을 많이 가져가는 방식이라, 관절만 놓고 재생해도 그림이 움직인다.
  한 번이라도 직접 칠하면 그 관절은 자동에서 빠지고, `자동` / `직접` 칩으로 되돌릴 수 있다
- 영향 영역 칠하기 — **한 획이 하나의 획이다.** 빠르게 그어도 끊기지 않고(점이 아니라 선분으로
  칠한다), 같은 자리를 오래 문질러도 한 겹만 얹힌다. 더 진하게 하려면 손을 떼고 다시 긋는다
  (크기는 실제 크기가 보이는 점 버튼 28단계, 가중치는 눈금 그래프로 조정)
- 영향 영역의 **모두 채우기**는 실루엣의 빈 정점을 가까운 관절 값으로 채우고, **정리**는 고립된
  오점과 희미한 잔여 영역을 걷어낸 뒤 생긴 틈까지 메운다. 두 작업 모두 `약하게` · `보통` · `강하게`
  중에서 범위를 고르며, 강하게 채우면 50% 이하 가중치도 다시 채운다. 전체 관절 확인창, 변경 개수
  안내와 실행 취소를 지원한다
- 가중치를 바꾸면 캔버스 브러시 커서의 진하기 · falloff와 크기 버튼의 점 진하기가 함께 바뀐다
- 칠하기는 이미지가 그려진 영역 안쪽에만 들어간다 (투명 배경 기준 클리핑)
- 영향 영역은 **채운 면**으로 보이고, 가중치가 그대로 불투명도가 된다. 옅으면 조금만 따라오고
  진하면 통째로 따라온다는 뜻이라 보이는 대로 움직인다. `전체 보기`로 빈 곳도 한눈에 확인
- 관절마다 다른 색이 자동으로 붙고, 원형 팔레트에서 직접 고를 수 있다
- 여러 개인 부위는 순서대로 어긋나 움직인다 (Track의 `stagger`). 다리 둘은 좌우 교대,
  넷은 네 박자, 스무 개는 앞에서 뒤로 흐르는 파도가 된다
- 무기를 쥔 쪽을 알아본다 (Track의 `focus`). 팔이 여섯이어도 검을 든 팔만 크게 휘두르고
  나머지는 거드는 정도로 움직인다. 무기가 없으면 예전처럼 전부 똑같이 공격한다
- 프리셋 23종 — 전부 JSON 데이터다
  - 기본 6: `대기` `걷기` `피격` `사망` `점프` `포효`
  - 이동 3: `달리기` `비행` `헤엄`
  - 반응 4: `방어` `회피` `기절` `승리`
  - 공격 10: `공격` `물기` `할퀴기` `휘두르기` `찌르기` `몸통박치기` `캐스팅` `돌진` `회전 베기` `내려찍기`
  - 서로 성격이 겹치지 않게 만들었다. 공격은 몸이 앞으로 나가며 한 번 크게 내지르고,
    할퀴기는 제자리에서 짧게 두 번 긁고, 돌진은 몸 전체가 멀리 나가 그 자리에 선다
  - 사망은 무릎이 꺾이고 몸이 81도 기울어 쓰러진다. 찌그러짐은 바닥에 닿는 순간에만 온다
- 애니메이션 이름은 더블클릭해서 자유롭게 바꾼다. 이 이름이 게임에서 부를 이름이다
- 하단 줄은 **가진 애니메이션**(누르면 재생), `+`로 여는 목록은 **고르는 곳**이다.
  고르면 아래 줄에 담기고 바로 재생된다. 이미 담은 것은 `담김`으로 표시된다
- 하단에서 애니메이션을 넣고 빼고, `−`로 내보내기에서만 제외(숨김)
- **좌우 반전이 애니메이션마다 따로다.** 하단의 `좌우 반전`을 켜면 그 동작만 반대쪽으로 나간다.
  오른쪽을 보고 걷다가 왼쪽으로 후려치게 만들 수 있다. 내보내기와 런타임까지 따라간다
- **`설정 → 좌우 뒤집기`는 다른 일이다.** 그림 · 관절 자리 · 칠한 영역을 **실제로 옮긴다**.
  왼쪽을 보는 그림을 아예 오른쪽을 보게 만드는 용도이며, 파일에는 아무 표시도 남지 않는다
  (한 번 더 누르면 돌아온다)
- 애니메이션마다 길이(0.1~10초) · 속도(0.1~3배) · 강도(0~2배) · 흔들림(0~2배)을 조절한다.
  **강도는 움직임의 세기**(위치 · 회전 · 크기 전부), **흔들림은 회전 계열에만** 한 번 더 걸린다 —
  나아가는 거리는 그대로 두고 도는 느낌만 조절할 수 있다.
  값은 파일에 저장되어 게임까지 따라간다. 길이를 바꾸면 키와 이벤트 시각이 같은 비율로
  함께 움직여 동작의 모양은 그대로다
- 따라 흔들림 — 꼬리 · 머리카락 · 망토처럼 `secondary` 태그가 붙은 부위가
  몸을 한 박자 늦게 따라 흔들린다 (Track 없이 런타임이 자동으로 만든다)
- **휴대폰에서도 파일을 받는다.** 공유 시트(파일 앱 · 드라이브 · 메신저)로 넘기고,
  없으면 내려받기, 그것도 막히면 새 탭으로 연다. 어느 쪽으로 갔는지 상태줄에 적는다
- `내보내기`: 숨기지 않은 애니메이션만 담은 `<이름>.export.zip`.
  격자는 파일에 넣지 않고 읽을 때 다시 만들어 파일이 작다 (같은 캐릭터 264KB → 38KB).
  파일 맨 앞에 `_readme` 한 줄이 붙어 열자마자 무엇이고 어떻게 재생하는지 알 수 있다
- **스프라이트 시트로 굽기** — 숨기지 않은 애니메이션이 하나도 빠짐없이 각각 한 장씩 나온다.
  `sheets.zip` 안에 애니메이션별 png와 `sheets.json`(칸 크기 · 열 · 행 · fps · 원점).
  게임에서 도는 것과 완전히 같은 경로로 굽고, 팔을 크게 휘둘러도 잘리지 않게 칸 크기를 잰다
- 프로젝트 저장 · 불러오기 (`character.puppet.zip` = puppet.json + 원본 이미지)
- Undo / Redo (`Ctrl+Z`, `Ctrl+Y` 또는 `Ctrl+Shift+Z`), 저장 `Ctrl+S`
- **자동 저장** — 손을 멈추면 브라우저(IndexedDB)에 담아 둔다. 탭을 닫거나 브라우저가
  죽어도 다시 열면 이미지 · 관절 · 칠한 영역 · 애니메이션이 그대로 이어진다.
  `파일 → 새 프로젝트`를 누르면 담아 둔 것도 함께 지운다

## 폴더 구조

```text
src/
 ├ core/            # 엔진 독립 로직 (렌더러 · UI에 의존하지 않는다)
 │  ├ format/       # Puppet JSON 타입, 상수, 생성 · 검증
 │  ├ skeleton/     # Bone 조회 · 계층 정렬 · 부모 변경 검사 · 스킨 변환
 │  ├ mesh/         # 격자 Mesh 생성
 │  ├ weight/       # 영향 영역 계산 · 정규화
 │  ├ animation/    # 키프레임 보간 · 태그 대상 찾기 · 재생
 │  ├ image/        # 도트 그림 자동 판정
 │  └ physics/      # 따라 흔들림 (Secondary Motion)
 ├ editor/          # 편집기 전용 코드
 │  ├ ui/           # DOM UI
 │  ├ tools/        # 이미지 불러오기 등 편집 도구
 │  ├ state/        # 편집기 상태 스토어
 │  └ history/      # Undo / Redo
 ├ renderer/
 │  └ phaser/       # 편집 캔버스 (Phaser Scene)
 ├ main.ts          # 조립 지점
 └ style.css
tests/              # 코어 로직 테스트 (Vitest)
docs/               # 포맷 문서
```

## 설계 원칙

- 스켈레톤 타입(인간형 · 4족보행 등)을 만들지 않는다. 모든 캐릭터는 노드와 부모 관계의 집합이다.
- 애니메이션은 Bone 이름이 아니라 **태그**를 대상으로 한다. 없는 태그는 조용히 건너뛴다.
- Editor와 Runtime, Renderer와 Animation 로직을 분리한다.
- Puppet JSON이 단일 소스다. 엔진별 파일을 따로 원본으로 두지 않는다.

## 배포

`main` 브랜치가 갱신되면 Vercel이 정적 사이트로 자동 배포한다 (`vercel.json`).
서버와 데이터베이스는 사용하지 않는다.
